Phase 3 Roadmap - App-Owned Cache Implementation

Goal

Phase 3 now delivers an application-owned Databridges price cache, a weekly asynchronous full refresh process, and shared country food baskets for the Price Bulletin drafter. The app must stop depending on the unavailable external AWS cache while still keeping country selection fast.

Guiding Principles

  1. Build the cache inside the app architecture, not as a dependency on the unavailable external AWS database.
  2. Target the beta deployment on GCP, including the cache database and asynchronous worker.
  3. Run full Databridges downloads outside the user request path.
  4. Refresh the entire monthly price database weekly and publish it atomically.
  5. Keep the previous cache active if the weekly refresh fails.
  6. Use DataBridges API metadata to drive basket choices and units.
  7. Remove fixed food basket behavior from active Price Bulletin calculations.
  8. Record cache version and basket version on every generated bulletin.

Phase 0 - DataBridges And Baseline Audit

Goal: Lock the exact current behavior and the Databridges API surfaces required for the cache.

Work Items

  • Inventory current Price Bulletin country selection, metadata loading, row loading, stats, charting, and DOCX code paths.
  • Inventory fixed food basket constants, heuristics, prompts, and graph dependencies.
  • Confirm the current app's Databridges credential variables and host configuration.
  • Map DataBridges client calls needed for monthly prices, commodities, units, markets, and currencies.
  • Confirm required scopes for monthly prices and metadata endpoints.
  • Define canonical monthly price uniqueness key from DataBridges fields.
  • Confirm GCP beta resource choices for Cloud SQL, scheduler, worker container, and secrets.

Exit Criteria

  • Engineering has a precise list of files/endpoints to change.
  • DataBridges endpoint plan and cache schema assumptions are documented.

Phase 1 - GCP App-Owned DB Foundation

Goal: Create the persistent cache storage layer under app control.

Work Items

  • Implement schema migrations for Cloud SQL PostgreSQL covering cache versions, active version pointer, countries, commodities, markets, currencies, and monthly prices.
  • Implement PriceCacheRepository with active-version reads.
  • Add local/test fixtures for countries, commodities, units, markets, and price rows.
  • Add indexes for country/date, country/commodity/date, and country/market/date queries.
  • Add config for GCP database URL or secret reference, backend type, and version retention.

Tests

  • Repository returns country metadata from fixtures.
  • Repository returns price windows by country, commodity, market, and date.
  • Active version pointer controls which rows are visible.

Exit Criteria

The app can read Price Bulletin-compatible data from an app-owned cache repository.

Phase 2 - DataBridges Ingestion Adapter

Goal: Wrap the official DataBridges client in a service suitable for large refresh jobs.

Work Items

  • Add a DataBridgesClientAdapter using data_bridges_client and WfpApiToken.
  • Make host, environment, page size, worker count, and request timeout configurable.
  • Implement paginated fetch for MarketPricesApi.market_prices_price_monthly_get.
  • Implement metadata fetch for commodities, units, markets, and currencies.
  • Add retry and backoff handling for rate limits and transient API errors.
  • Normalize API objects into cache row dictionaries.

Tests

  • Adapter paginates multiple pages correctly.
  • Adapter refreshes or reuses access tokens correctly.
  • Monthly price normalization maps required fields.
  • Transient failures are retried and permanent failures are surfaced.

Exit Criteria

The app can fetch and normalize Databridges monthly price data in a worker context.

Phase 3 - GCP Weekly Full Refresh Worker

Goal: Build the weekly asynchronous ex novo cache rebuild.

Work Items

  • Add a GCP scheduler entry for weekly refresh.
  • Package the refresh code as a Cloud Run Job or equivalent GCP worker container.
  • Implement a refresh lock so overlapping full refreshes cannot run.
  • Create a new cache version with status building.
  • Download metadata and all monthly price rows from Databridges. Prefer country-chunked ingestion if it improves resumability and monitoring.
  • Write rows to staging for the new cache version.
  • Run validation: required fields, duplicate keys, row counts, country coverage, latest dates.
  • Promote the new version atomically if validation passes.
  • Keep the old active version if validation fails.
  • Record refresh logs and admin-visible status.
  • Clean up old versions according to retention policy.

Tests

  • Successful refresh creates and activates a new cache version.
  • Failed refresh leaves previous active version unchanged.
  • Refresh lock blocks concurrent refreshes.
  • Validation catches duplicate canonical keys and missing required fields.

Exit Criteria

A scheduled or manually invoked worker can rebuild the full cache and publish it without blocking users.

Phase 4 - Cache-First Price Bulletin

Goal: Move the user-facing Price Bulletin flow onto the active cache version.

Work Items

  • Change country list and selected-country metadata loading to use PriceCacheRepository.
  • Load commodities, units, markets, regions, date range, and latest cached date from active cache.
  • Drive the reference-month dropdown from basket-aware reportable months, not the broad country cache date range.
  • Replace report data loader live Databridges calls with cache reads.
  • Add cache status panel with active version ID, last refresh time, and warnings.
  • Handle empty or missing cache states with clear admin-facing and user-facing messages.

Tests

  • Country selection does not call Databridges.
  • Forecast-only or incomplete basket months are not selectable as reference months.
  • Reportable-month endpoints work through both the FastAPI router and the Streamlit local dispatcher.
  • Report generation works from fixture cache rows.
  • Cache status appears in the form.

Exit Criteria

Users can generate Price Bulletin outputs from the app-owned cache.

Phase 5 - Shared Country Food Baskets

Goal: Replace fixed baskets with shared country basket configurations.

Work Items

  • Create shared basket tables and repository methods.
  • Implement basket versioning and active country pointer.
  • Add basket validation using cached commodity and unit metadata.
  • Add basket summary and editor inside the Price Bulletin form.
  • Warn users that saved changes affect future bulletins for that country.
  • Record who changed the basket and when.

Tests

  • Invalid baskets are rejected.
  • Saving a basket creates a new active country version.
  • A basket saved by one user is visible to another user.

Exit Criteria

Users can create, view, and edit the shared basket for a country from the Price Bulletin form.

Phase 6 - Basket Calculation And Graph Integration

Goal: Use saved baskets in all Price Bulletin basket values, graphs, and narrative inputs.

Work Items

  • Remove fixed basket logic from active calculations.
  • Implement weighted basket calculation: price multiplied by saved weight or quantity.
  • Add national and regional aggregation support.
  • Add missing-component coverage metadata.
  • Update basket graph and report statistics to use calculated basket series.
  • Keep historical overlays readable: show prior-year and full five-year same-month overlays on food-basket and single-commodity charts only.
  • Require five prior same-calendar-month cached observations before plotting a five-year average or range label.
  • Update DOCX and prompt inputs to include basket version and coverage warnings.

Tests

  • Known fixture basket produces expected monthly values.
  • Changing weights changes graph data.
  • Missing commodity prices produce explicit warnings.
  • Multi-commodity charts remain current-period only, while food-basket and single-commodity charts keep valid overlays.
  • Short cache history does not produce a five-year average or range label.

Exit Criteria

Generated Price Bulletins use the saved country basket in calculations, charts, and report text.

Phase 7 - Manual Latest Refresh And Audit

Goal: Preserve a controlled freshness path while keeping the weekly cache as the source of normal reads.

Work Items

  • Add feature-flagged manual latest refresh for freshest available rows between weekly refreshes.
  • Fetch all priced commodities for the gap between the latest reportable cached basket month and the current month only after user action.
  • Filter non-real rows, deduplicate against active country cache rows, and skip existing canonical rows.
  • When new usable rows exist, create and activate a country-specific cache version without changing the global active cache pointer.
  • Record source cache version, new country cache version, skipped rows, missing months, and basket version in refresh metadata.
  • Apply exchange-rate usability diagnostics before report FX sections, charts, and module narratives are populated.
  • Omit or replace misleading official-only, near-static, price-scale-inconsistent FX while preserving stable pegs with plausible price scales.
  • Add admin sync status page or panel for weekly refresh history.

Tests

  • Manual refresh updates only the selected country's active cache version.
  • Forecast-only refresh responses return no update and leave cache pointers unchanged.
  • Manual refresh endpoints work through both the FastAPI router and the Streamlit local dispatcher.
  • Stale basket versions return a conflict so the form can refetch basket/reportable-month state.
  • Refresh metadata captures source cache, new country cache, skipped rows, and missing basket coverage.
  • FX usability diagnostics suppress misleading official-only nominal rates, protect plausible stable official rates, and preserve fallback behavior.

Exit Criteria

Users and admins can see exactly which cache version and optional manual country refresh data were used.

Phase 8 - Hardening And Rollout

Goal: Make Phase 3 reliable enough for pilot use.

Work Items

  • Add performance checks for country metadata and report data queries.
  • Add refresh observability: duration, rows fetched, rows written, failures, latest date by country.
  • Add operational runbook for manual refresh trigger, failed refresh, rollback, and credential rotation.
  • Feature-flag cache-first reads, basket editor, weekly refresh, and manual latest refresh.
  • Document first cache bootstrap procedure.
  • Define cleanup policy for old cache versions.

Exit Criteria

  • Weekly full refresh works and is observable.
  • Failed refresh leaves active cache intact.
  • Country selection and report generation are cache-first.
  • Saved country baskets drive basket calculations and graphs.
  • Run metadata records cache and basket provenance.

Open Decisions

  • Exact GCP resource names, deployment project, service accounts, and secret storage pattern.
  • Whether scheduled refreshes should activate cache versions globally only or allow per-country activation if one country fails validation.
  • Initial bootstrap date range for the complete historical price database if Databridges requires date bounds.
  • Who can edit shared country baskets.
  • Whether manual latest refresh should remain all priced commodities or later narrow to basket plus selected extras.
