1. Executive Summary

Headline finding (F1 — Critical): report generation fails for every country because the Databridges monthly price endpoint (ViewExtendedMonthlyAggregatedPrice DTO) does not contain admin1/admin2 fields at all. The refresh worker stores every cached price row with admin1_name = NULL, the serving path renders NULL as "Unknown", and the Price Bulletin form (which builds its region list from market metadata, where admin1 is present) therefore submits region names that can never match. The pre-cache implementation joined market metadata onto price rows to obtain Admin 1; that join was dropped when the cache pipeline was introduced. No re-download is required to fix the deployed database — a single SQL backfill joining cached_markets onto cached_price_monthly repairs the active cache immediately (see Section 6).

The audit confirms the overall cache architecture (versioned snapshots, atomic per-country activation, refresh lock, validation, retention) is sound and well tested at the unit level. However, five distinct defects/gaps combine to produce the symptoms observed in production:

Beyond the cache focus, the broader audit (Part A) finds that the Phase 1 spec (chat agent, Claude-on-Vertex) and the Phase 2 spec (authentication, workspaces, model registry) are not implemented — the app remains the four-wizard alpha with a Gemini/Vertex singleton — and Phase 3 itself is roughly half done: its roadmap phases 0–4 (audit, DB foundation, ingestion adapter, refresh worker, cache-first bulletin) are delivered; phases 5–8 (shared country food baskets, basket-driven calculations, manual latest overlay, admin status UI, hardening) are not started. Two security/operations items also need attention: a plaintext Google API key in app/docker.env is copied into the production container image, and a dead 151 MB CSV is baked into every image build.

Remediation status (2026-06-10, same branch): findings F1–F6 have been fixed in code following this audit.
  • F1: the refresh worker now enriches price rows with admin1/admin2/market/commodity metadata from the markets and commodities fetched in the same pass (_enrich_price_rows_with_metadata); get_price_window() and the availability regions query LEFT JOIN cached_markets with COALESCE as defense in depth; and migration 003_admin_backfill_and_price_key backfills the deployed database automatically on the next app/worker start — no re-download needed.
  • F2: the canonical key now includes price_type_id, currency_id, and commodity_unit_id (dedup + a new unique index replacing the old primary key); dual-currency series are both cached, and the report path selects a single currency per run (requested currency → country default → most frequent) instead of averaging across currencies, with an officer-visible note when multiple currencies exist.
  • F3: composite flags such as "actual,aggregate" are now parsed component-wise and kept, at both ingest and read time.
  • F4 (code side): the warning sanitizer no longer hardcodes "403 Forbidden"; it surfaces the actual stored error. The gateway entitlement request for CommodityUnits/List remains an external action.
  • F5: future-dated rows are excluded at ingest with an explicit per-country warning; the UI month cap remains as defense for older cache versions.
  • F6: cache warnings are now split by audience — officers see freshness/coverage warnings; ETL telemetry (dedup counts, flag exclusions, units fetch errors) moves to operator_warnings, rendered on the bulletin form inside a collapsed "Cache processing notes (for administrators)" expander.
Verified by 7 new regression tests (DTO-faithful worker fixtures, market-join enrichment, dual-currency retention and read-time currency selection, composite flags, future-date exclusion, legacy-database migration backfill); full suite: 69 passed, 2 skipped.

2. Part A — General Implementation Audit (Phases 1 → 3)

4. Part C — Symptom-By-Symptom Diagnosis Of The Reported Issues

4.1 "Requested regions are not available… Available regions: ['Unknown']" — all countries (→ F1)

Root cause chain, fully verified in code:

  1. The official monthly price model venv/…/data_bridges_client/models/view_extended_monthly_aggregated_price.py contains no admin1/admin2 properties — its full field list is commodity/market/priceType/unit/currency IDs and names, country, dates, price, observations, flag, source, frequency.
  2. normalize_monthly_price_row() (app/services/price_cache/databridges_adapter.py:505-506) looks for admin1Name/adm1Name/admin1_name/adm1_name — never present — so every normalized row carries admin1_name=None.
  3. insert_country_snapshot() (sql_repository.py:649) writes the NULL through to cached_price_monthly.admin1_name. The worker fetches markets (which do have admin1) into cached_markets but never joins them onto the price rows.
  4. At read time, _normalise_cached_price_rows() (market_monitor/data_loader.py:745) maps row.admin1_name or "Unknown" — so the report dataframe has Admin 1 == "Unknown" for every row, and get_price_window() (sql_repository.py:344) reads only cached_price_monthly, no join.
  5. The form's region multiselect, however, is populated from get_country_metadata() → availability.admin1_names (empty, because all price-row admin1 are NULL) → fallback to market metadata (data_loader.py:340-342), which returns the real names (Barisal, Kabul, Akkar, …). All regions are selected by default (pages/3_Price_Bulletin_Drafter.py:221-226).
  6. extract_time_series_from_csv() then intersects the submitted names with {"Unknown"} and raises (data_loader.py:471-478) — exactly the error reported for BGD, AFG, and LBN.

Why this regressed: the pre-cache loader explicitly enriched each price row from a market lookup — "Admin 1": market.get("admin1_name") … via _market_lookup() (verified in git show 17a398f~1). The cache migration (commit 17a398f "Implement cache-first price bulletin") dropped that join; _market_lookup() survives in the new loader as dead code (data_loader.py:837).

Why tests did not catch it: every fixture invents admin1_name directly on price rows (fixtures.py:197-202, tests/test_price_cache_refresh_worker.py:73-87), a shape the real API never returns. See Section 7.

4.2 "Deduplicated N duplicate monthly price row(s) across K canonical key(s)" (→ F2)

The dedup key (CANONICAL_PRICE_KEY_FIELDS, validation.py:8-15) and the table primary key (migrations/…/001:105-113) are (country, commodity_id, market_id, price_date, price_type_name, price_flag). They exclude currency_id, commodity_unit_id and price_type_id. Databridges legitimately publishes multiple rows per that key — most obviously dual-currency quotes (Lebanon: LBP and USD for the same commodity/market/month/price-type) and unit variants. The numbers reported are consistent with this: Lebanon 960 duplicate rows across exactly 960 keys = one dropped row per key = currency pairs; Afghanistan 9,401/8,377; Bangladesh 7,119/6,624. Commit 1092625 added the dedup to stop IntegrityError on insert — i.e. the symptom (PK violation) was fixed by silently discarding one of the conflicting series per key, keeping whichever row ranks higher on metadata completeness/observations (refresh_worker.py:560-585). Besides losing data, the survivor per key is currency-arbitrary, so a commodity's monthly series can mix currencies across months. The Phase 0 audit explicitly flagged this exact collision risk ("Name-only fields… may not be sufficient for durable uniqueness") — the risk materialized unmodified.

4.3 "Excluded N non-real monthly price row(s) … (actual,aggregate=…, forecast=…)" (→ F3, plus by-design behavior)

Two different things are inside these messages:

  • By design: forecast rows are excluded (commit 337cafb), which is correct for a bulletin grounded in observed prices (AFG 29,366; BGD 11,934; LBN 15,900 forecast rows).
  • Defect: the flag filter (refresh_worker.py:498-512) tests the whole string against {"", "actual", "aggregate", "aggregated"}. Databridges emits composite flags such as "actual,aggregate"; these are real observations but are excluded (BGD 3 rows, AFG 431 rows). The same whole-string test exists at read time (_ALLOWED_PRICE_FLAGS, data_loader.py:34 and :727-729), so even after a backfill these rows would be dropped from reports. The filter should split the flag on commas and check that every component is real.

4.4 "CommodityUnits/List could not be fetched from Databridges (403 Forbidden)" (→ F4)

The Cloud Run job's API credentials are rejected with 403 specifically on CommodityUnits/List (the adapter correctly treats 403 as permanent, databridges_adapter.py:20). Commodities, markets, monthly prices, and currencies succeed with the same token, so this is an API gateway subscription/product entitlement gap for the CommodityUnits endpoints, not a code bug — it must be resolved with the WFP API gateway team (the Phase 0 audit lists CommodityUnits/List and Conversion/List as required endpoints). The worker's fallback (derive units from commodity and price rows, refresh_worker.py:127-139, 607-628) keeps unit names flowing but loses conversion_to_kg_l, which Phase 3's basket work (roadmap phase 5/6) will need. Two cosmetic issues: the sanitizer (data_loader.py:1150-1156) hardcodes "(403 Forbidden)" into the user-facing string whatever the actual error was, and the warning is repeated to every officer on every country (see F6).

4.5 "Found 66 price metadata references not present in fetched commodities/markets" — Bangladesh (→ F-INFO)

Counted in validation.py:98-103: each price row whose commodity_id is missing from Commodities/List counts one reference, and likewise for market_id vs Markets/List — 66 is a reference count, not a row count. Rows are still cached (warning, not error), which is reasonable. Two consequences worth knowing: (a) such commodities cannot be selected in the form (the metadata commodity list comes from cached_commodities filtered to priced IDs, data_loader.py:321-324); (b) price rows referencing unknown market_ids will keep admin1=NULL even after the F1 join fix and should be reported per-market in the warning to make triage possible.

4.6 "PriceCache contains future-dated monthly prices… capped at the current month (2026-06)" — Bangladesh (→ F5)

After forecast exclusion, BGD still has rows dated after June 2026 with flags in the allowed set (most plausibly aggregate rows built from forecasts upstream, or upstream data-quality slips). Commit 3a1a9da handles this at the UI layer only: month options and the latest-cached-date are capped (data_loader.py:1170-1183), but the future rows remain in the cache and in cached_countries.latest_price_date, and get_price_window() will happily return them for a window that includes them. Recommended: investigate the offending BGD rows (one SQL query, see Section 6), then either exclude future-dated rows at ingest (with a warning) or store both raw and capped latest dates.

4.7 The overall "wall of warnings" (→ F6)

All of the above strings are written into the cache version's validation_summary_json by the worker and re-surfaced verbatim per country by _country_cache_warnings() → metadata.warnings → st.warning(...) on the form (pages/3_Price_Bulletin_Drafter.py:150-151) and again inside report generation warnings. These are ETL operator telemetry, not officer-actionable information. The Phase 3 roadmap (phase 7) plans an admin sync-status panel — that is the right home. Officers should see only: cache freshness, coverage of the selected period, and anything affecting their selected commodities/regions.

6. Remediation Plan (Prioritized)

6.1 P0 — Unblock report generation today (F1), no re-download needed

Step 1 — backfill the deployed Cloud SQL database (run once; idempotent; covers every retained version):

UPDATE cached_price_monthly p
SET    admin1_name = m.admin1_name,
       admin2_name = COALESCE(NULLIF(p.admin2_name, ''), m.admin2_name),
       market_name = COALESCE(NULLIF(p.market_name, ''), m.market_name)
FROM   cached_markets m
WHERE  m.cache_version_id = p.cache_version_id
  AND  m.country_iso3     = p.country_iso3
  AND  m.market_id        = p.market_id
  AND  (p.admin1_name IS NULL OR p.admin1_name = '');

Then clear the in-process TTL caches (restart the Cloud Run service, or wait 15 minutes) and verify with:

SELECT country_iso3,
       COUNT(*) FILTER (WHERE admin1_name IS NULL OR admin1_name = '') AS rows_without_admin1,
       COUNT(*) AS rows_total
FROM   cached_price_monthly
GROUP  BY country_iso3 ORDER BY rows_without_admin1 DESC;

Step 2 — durable fix in the worker (refresh_worker.py::_refresh_country): after fetching markets, build {market_id: market} and set admin1_name/admin2_name (and market_name/commodity_name fallbacks) on each price row before validation/insert — this restores exactly what the pre-cache loader did via _market_lookup().

Step 3 (optional, defense in depth) — in get_price_window(), LEFT JOIN cached_markets and COALESCE(p.admin1_name, m.admin1_name) so a future ingest regression cannot blank regions again.

6.2 P1 — Stop silent data loss (F2, F3)

  • Migration 003: extend the cached_price_monthly uniqueness to include currency_id, commodity_unit_id, price_type_id (use COALESCE(x, -1) in a unique index if NULLs are possible); extend CANONICAL_PRICE_KEY_FIELDS identically.
  • Keep _deduplicate_monthly_price_rows only for residual exact duplicates; log keys whose duplicates differ in price as data-quality diagnostics, per market/currency.
  • Define the read-time currency policy before re-running a full refresh (multi-currency countries like Lebanon will then have both series in the cache): simplest is to prefer the country's configured currency in extract_time_series_from_csv and surface the choice in metadata; the bulletin currency field already exists in the form.
  • Fix the flag filter (both worker and loader) to treat comma-composite flags componentwise.
  • Re-run the full refresh after these land. Note F7 first: the drop-ratio guard will compare against pre-fix counts — expect to need the like-for-like comparison fix (or a one-time override) to avoid countries failing validation spuriously.

6.3 P1 — API entitlement (F4)

Open a request with the WFP API gateway team to add CommodityUnits/List (and CommodityUnits/Conversion/List) to the application's subscription for the api://wfp-api-mediation-service/.default scope. The basket phases (roadmap 5–6) need unit conversions; the current fallback only yields unit names.
